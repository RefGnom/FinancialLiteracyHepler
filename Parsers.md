# Модуль парсинга файлов выгрузок

## Назначение
Модуль отвечает за чтение файлов транзакций, выгруженных из онлайн-банков (CSV, XLSX, PDF), и преобразование их во внутреннее **сырое представление** (`RawTransaction`) с одновременной фиксацией ошибок. Парсеры **не знают** о доменной модели – они только извлекают данные и возвращают результаты парсинга. Бизнес‑логика импорта (проверка дубликатов, создание доменных транзакций, сохранение) реализована в Application слое.

## Расположение в проекте
- Проект: `FinancialDiscipline.Infrastructure`
- Зависимости: `FinancialDiscipline.Domain` (не требуется, если `RawTransaction` определён в Infrastructure)
- Библиотеки: CsvHelper, ClosedXML (или EPPlus), PdfPig (или iTextSharp)

## Сырые данные (RawTransaction)
`RawTransaction` – простой DTO без бизнес-логики.

```csharp
public class RawTransaction
{
    public DateTime Date { get; set; }
    public decimal Amount { get; set; } // положительная или отрицательная
    public string Description { get; set; } = string.Empty;
    public string? AccountId { get; set; }
    public string? Mcc { get; set; }
    public decimal? Cashback { get; set; }
    public string Currency { get; set; } = "RUB";
    public Dictionary<string, string> RawData { get; set; } = new(); // все исходные колонки, но с единообразными ключами
}
```

В RawData все ключи приводятся в единому формату. Каждый парсер должен имена колонок уметь преобразовывать в единый формат ключей.

## Результат парсинга (ParsingResult)
Парсер возвращает коллекцию `ParsingResult` – каждый элемент либо содержит `RawTransaction`, либо ошибку.

```csharp
public class ParsingResult
{
    public bool IsSuccess { get; }
    public RawTransaction? Transaction { get; }
    public ParsingError? Error { get; }
}

public class ParsingError
{
    public int RowNumber { get; set; }          // номер строки в исходном файле
    public string? ColumnName { get; set; }     // наименование колонки (если применимо)
    public string Message { get; set; } = string.Empty;
    public string RawLine { get; set; } = string.Empty; // для отладки
}
```

## Интерфейс парсера

```csharp
public interface ITransactionParser
{
    bool CanParse(string filePath);
    IEnumerable<ParsingResult> Parse(Stream fileStream, ParsingProfile profile);
}
```

## Профили парсинга (ParsingProfile)
Поскольку один формат файла может соответствовать разным банкам, вводится понятие **профиля**. Профиль определяет все правила чтения конкретного типа выписки.

Пример профиля в `settings.json`:

```json
"ParsingProfiles": [
  {
    "Name": "TinkoffCSV",
    "FileType": "CSV",
    "Delimiter": ",",
    "Encoding": "utf-8",
    "HasHeader": true,
    "DateFormats": ["dd.MM.yyyy HH:mm:ss", "yyyy-MM-dd"],
    "Mapping": {
      "Date": "Дата операции",
      "Amount": "Сумма операции",
      "Description": "Описание",
      "AccountId": "Номер карты",
      "Mcc": "MCC",
      "Cashback": "Кэшбэк"
    }
  },
  {
    "Name": "SberbankCSV",
    "FileType": "CSV",
    "Delimiter": ";",
    "Encoding": "windows-1251",
    "HasHeader": false,
    "ColumnsOrder": [0, 1, 2],
    "DateFormats": ["dd.MM.yyyy"]
  }
]
```

Поля профиля:
- `Name` – уникальное имя профиля.
- `FileType` – `CSV`, `XLSX` или `PDF`.
- Для CSV: `Delimiter`, `Encoding`, `HasHeader`, `ColumnsOrder` (если заголовка нет), `DateFormats`, `Mapping` (сопоставление имён колонок с полями `RawTransaction`).
- Для XLSX: `SheetIndex` (или `SheetName`), `FirstRowIsHeader`, `Mapping`.
- Для PDF: эвристические настройки (регулярные выражения).

**Отсутствие эвристик внутри строк:** если профиль не предоставляет явного `Mapping` или `ColumnsOrder`, парсер не пытается угадать колонки – выбрасывается ошибка.

## Автоопределение профиля (эвристика только на уровне выбора профиля)
- Если пользователь не указал `--profile`, система анализирует первые строки файла (или заголовки) и пытается сопоставить их с заголовками во всех зарегистрированных профилях.
- Если найден один профиль – CLI запрашивает подтверждение: `"Обнаружен профиль 'TinkoffCSV'. Использовать? (y/n)"`. При `n` – переход к интерактивному выбору.
- Если несколько – выводится список для выбора.
- Если ни один не подошёл – ошибка с предложением указать профиль вручную или создать новый (через `config profiles add`).

## Импорт и обработка ошибок (Application слой)

Команда импорта в CLI:  
`import <file> [--profile <name>] [--validate]`

### Без флага `--validate`
1. Парсер возвращает `IEnumerable<ParsingResult>`.
2. Успешные результаты (`IsSuccess = true`) преобразуются в доменные транзакции (с проверкой дубликатов, установкой валюты, типа и т.д.) и сохраняются через репозиторий.
3. Ошибочные результаты (`IsSuccess = false`) **не сохраняются**.
4. Если есть ошибки:
   - Создаётся файл с ошибками в том же формате, что и исходный, с добавлением колонки `_Error`. Например, для CSV – добавляется колонка, в которую записывается текст ошибки.
   - Имя файла: `<original>_errors.<ext>`.
   - Пользователю выводится сообщение: `"Импорт завершён. Успешно: X, ошибок: Y. Исправьте ошибки в файле '..._errors.<ext>' и выполните импорт заново."`
5. Если ошибок нет – просто выводится успешная статистика.

### Флаг `--validate`
- Парсинг выполняется, но успешные транзакции **не сохраняются**.
- Генерируется файл с ошибками (если они есть) и выводится статистика.
- Полезно для предварительной проверки файла перед реальным импортом.


## 1. CSV парсер

**Особенности:**
- Использует `CsvHelper`.
- Чтение потоковое (`yield return`).
- Для каждой строки:
  - Применяет `Mapping` из профиля.
  - Преобразует дату с учётом `DateFormats`.
  - Преобразует сумму (с учётом десятичного разделителя, знака).
  - В случае любой ошибки возвращает `ParsingResult` с ошибкой, содержащей номер строки и описание.
- **Никаких эвристик** для угадывания колонок – строго по профилю.

## 2. XLSX парсер

> **Статус:** `[FUTURE]` – реализация будет добавлена в одной из следующих версий. В текущей версии выбрасывает `NotImplementedException` с сообщением: `"XLSX парсер будет доступен в следующем релизе"`.

**Планируемая логика:**
- Использование `ClosedXML`.
- Чтение листа по индексу/имени.
- Маппинг колонок по заголовкам или порядковым номерам.
- Аналогичная обработка ошибок с указанием листа и строки.

## 3. PDF парсер

> **Статус:** `[FUTURE]` – реализация будет добавлена в одной из следующих версий. В текущей версии выбрасывает `NotImplementedException` с сообщением: `"PDF парсер будет доступен в следующем релизе"`.

**Планируемая эвристическая логика:**
- Извлечение текста через `PdfPig`.
- Поиск строк, похожих на транзакции, с помощью регулярных выражений из профиля.
- Все ошибки (не найдена дата, сумма) возвращаются как `ParsingResult` с указанием страницы и приблизительной позиции.

## Фабрика парсеров

```csharp
public class ParserFactory
{
    public ITransactionParser GetParser(string filePath);
}
```
- Выбор по расширению файла (`.csv` → CSV‑парсер, `.xlsx` → XLSX‑парсер, `.pdf` → PDF‑парсер).
- Если расширение не поддерживается – исключение.

## Управление профилями (CLI команды)

- `config profiles list` – показать все профили.
- `config profiles add` – интерактивное создание нового профиля (запрашивает все параметры). Сохраняет в `settings.json`.
- `config profiles edit <name>` – редактирование существующего.
- `config profiles delete <name>` – удаление.
- `config profiles default <name>` – установить профиль по умолчанию (используется, если не указан `--profile` и не сработала эвристика).

## Логирование
- Debug: каждая успешно извлечённая транзакция.
- Warning: ошибка парсинга строки (с деталями).
- Error: фатальная ошибка (неверный формат файла, отсутствие обязательных колонок в профиле).

## Тестирование
- Модульные тесты для каждого парсера с реальными файлами (в том числе с ошибками).
- Тесты на корректность генерации файла ошибок.

## Расширяемость
- Новый парсер – реализовать `ITransactionParser` и зарегистрировать в фабрике.
- Новый формат выписки – создать профиль через `config profiles add`, не меняя код.
